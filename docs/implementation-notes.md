# Кейс Performance Review — архитектурные решения

Страница: `page101071766.html` → ЧПУ `/perfomance_review_dlya_proizvoditelya` (правило в `htaccess`).

## Почему не Next.js

Задание предлагало стек Next.js + GSAP + Lenis + Rive. Репозиторий — статический сайт:
экспорт Tilda, самодостаточный бандл главной (`index.html` собирается `scripts/bundle_index.py`),
статика в `css/`, `js/`, `images/`, деплой обычным `rsync` на nginx. Ни npm-сборки, ни Node на проде нет.

Вводить Next.js ради одной страницы означало бы завести второй стек, второй пайплайн деплоя
и потерять совместимость с текущими rewrite-правилами. Поэтому страница построена
на существующих конвенциях репозитория, а задачи «тяжёлых» библиотек закрыты нативными API.

| Библиотека из задания | Чем заменена | Почему |
|---|---|---|
| GSAP + ScrollTrigger | IntersectionObserver + один rAF-цикл на `scroll` | Нужны прогресс, активная глава и reveal — этого достаточно, минус ~50 КБ |
| Lenis (smooth scroll) | Нативный скролл | Плавный скролл ломает `scroll-snap` на мобильных и мешает accessibility |
| Framer Motion | CSS-переходы по классам | Анимации декларативные, легко глушатся в reduced-motion |
| Rive / Lottie | Инлайновый SVG + Canvas 2D | Flow — простая четырёхлучевая форма, рантайм не нужен |
| Three.js | Canvas 2D | Сцены «хаос → порядок» плоские, WebGL избыточен |

## Flow — цифровой проводник

Четырёхлучевая искра из брендового sparkle-пути. Реализована двумя слоями:

1. **Фиксированный индикатор** (`.flow-guide`) — вертикальный рельс справа на desktop,
   горизонтальная полоса внизу на мобильных. Позиция = прогресс чтения, оттенок задаётся
   атрибутом `data-flow-tint` активной главы, счётчик показывает `NN / 09`.
2. **Частица внутри canvas-сцен** — в hero пытается пройти сквозь хаос документов и отталкивается
   от них, в блоке результатов свободно движется и связывает узлы линиями.

## Canvas-сцены

Один компонент `initCanvasScene(canvas, mode)` с двумя режимами:

- `chaos` — объекты дрейфуют хаотично, Flow отталкивается от близких документов;
- `order` — объекты стягиваются к целевой сетке, Flow рисует связи до ближайших узлов.

Оптимизации: DPR ограничен 2, количество объектов зависит от площади, rAF стартует и
останавливается по IntersectionObserver, resize задебаунсен. В reduced-motion рисуется
один статический кадр и цикл не запускается.

## Управление скроллом

Все scroll-зависимые вычисления собраны в один rAF-тик (`schedule()`), слушатель — `passive`.
Внутри тика: прогресс Flow, класс `is-stuck` у топбара, активная глава, активная станция
маршрута, активный шаг секвенции. Отдельных обработчиков скролла нет.

Scroll-jacking не используется: страница листается нативно, sticky-сцены сделаны
через `position: sticky`.

## Доступность

- Семантика: `main`, `section` с `aria-labelledby`, `blockquote`, `dl` для фактов.
- Skip-link к содержанию.
- Карта проекта — `role="tablist"` со стрелками, Home/End и roving `tabindex`.
- Модалка — focus trap, Escape, возврат фокуса на триггер.
- Canvas помечены `aria-hidden`, продуктовые сцены имеют текстовые `aria-label`.
- Контент читается без JS: preloader снимается только скриптом, но не перекрывает
  документ при отключённом JS, так как показывается поверх уже отрендеренной страницы.
- `prefers-reduced-motion`: sticky и абсолютное позиционирование сцен снимаются,
  все сцены показываются последовательно в финальных состояниях, счётчики выводят
  конечные значения, canvas рисует один кадр.

## Достоверность контента

Все цифры взяты из исходного кейса (см. `docs/case-study-content-map.md`).

Два места требуют внимания перед публикацией:

1. **Цитата** — в исходнике помечена как плейсхолдер под NDA. На странице сохранена плашка
   «Плейсхолдер — требуется согласование цитаты».
2. **Демо кадрового решения** — профили A/B/C синтетические, помечены `data-demo="true"`
   и видимой плашкой «Демо-данные · не из проекта клиента».
