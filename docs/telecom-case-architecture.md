# Телеком-кейс «Один AI. Три режима развития» — архитектура

Страница: `page101340001.html` → ЧПУ `/avtomatizatsiya-otsenki-po-keysam-v-telekome`
(правило в `htaccess`). Прежняя версия кейса `page96476846.html` остаётся в репозитории
как архив исходника и из навигации не открывается.

## Почему снова не Next.js

Задание предлагало Next.js + GSAP + ScrollTrigger + Framer Motion + Lenis + Rive + Three.js.
Репозиторий — статический сайт: экспорт Tilda, самодостаточный бандл главной
(`index.html` собирается `scripts/bundle_index.py`), статика в `css/`, `js/`, `images/`,
деплой обычным rsync на nginx. Ни npm-сборки, ни Node на проде нет. Предыдущая
customer success story (`page101071766.html`) уже построена на этих конвенциях —
см. `docs/implementation-notes.md`.

| Из задания | Чем закрыто | Почему |
|---|---|---|
| GSAP + ScrollTrigger | Один rAF-батченный тик на скролл | Нужны прогресс, активная глава, sticky-шаги и reveal — этого достаточно |
| Lenis | Нативный скролл | Кастомный скролл ломает доступность и `scroll-snap` |
| Framer Motion | CSS-переходы по классам | Легко глушатся в reduced-motion |
| Rive / Lottie | Инлайновый SVG | Сигнал и ветки — простые пути |
| Three.js | Canvas 2D | Сеть и карта профилей плоские, WebGL избыточен |

## Контентная модель

Все показатели и демо-данные лежат в `window.EF_TELECOM_CASE`. В разметке каждый
показатель помечен `data-fact="<id>"`, поэтому число на странице отслеживается
до записи в конфиге и далее до источника в fact-check.

Неподтверждённые значения помечены в конфиге комментарием
`// CLIENT_INPUT: confirm before production publication` и на странице выводятся
с видимой плашкой «Требует подтверждения». Демонстрационные данные — с плашкой
«Демонстрация интерфейса».

Режим раскрытия заказчика переключается одним полем
`EF_TELECOM_CASE.client.disclosure` (`'anonymous'` по умолчанию).

## Motion language: сигнал → узел → ветка → сеть

- **Preloader** — импульс проходит три узла, подписи меняются по мере прохождения.
- **Hero** — длинная волна ответа физически сжимается на первом скролле
  (`--squeeze`), рядом раскрывается компактный чат, вокруг загораются индикаторы.
- **Глава масштаба** — очередь участников растёт 10 → 100 → 1 000+ при неизменной
  «переговорной»; количество точек пересобирается по прогрессу секции.
- **Маршрутизатор** — SVG-пути рисуются через `stroke-dashoffset`, привязанный к
  прогрессу секции; ветки расходятся из общего ядра с разной задержкой.
- **Ветки** — каждая задаёт свою тему через `data-theme`, тема подхватывается
  переменной `--accent` и применяется ко всем вложенным элементам.
- **Конструктор** — sticky-панель, экран превью переключается по активному шагу.
- **Финал** — Canvas-сеть узлов, три цвета сходятся в одно поле.

Scroll-jacking не используется, sticky сделан через `position: sticky`.

## Единый scroll-тик

Все scroll-зависимые вычисления собраны в одну функцию `measure()`:
прогресс чтения, состояние топбара, сжатие волны, активная тема и ветка,
отрисовка путей маршрутизатора, стадия очереди, активный шаг конструктора,
а также появление блоков и заполнение полос.

Два решения, которые стоит знать при доработке:

1. **Тик не полагается только на событие `scroll`.** Программная прокрутка
   (deep-link, поиск по странице, встроенные webview) в ряде окружений событие
   не порождает — проверено на этом проекте. Поверх слушателя работает опрос
   позиции раз в 200 мс, который мгновенно выходит, если ничего не изменилось.
2. **Появление блоков считается в тике, а не через IntersectionObserver.**
   При резком программном переходе наблюдатель может не успеть отработать,
   и секция осталась бы с нулевой прозрачностью.

Флаг батчинга сбрасывается в `finally`: одна ошибка внутри тика не может
навсегда остановить обновление скролла.

## Canvas-сцены

Две сцены на общем компоненте `initNetworkCanvas` (hero и финал) плюс отдельная
карта профилей `initMap`.

Карта рисует 1 000 точек в Canvas, а не в DOM. Координаты генерируются
детерминированным ГПСЧ с фиксированным зерном, поэтому картина не меняется между
рендерами и не зависит от случайности. DPR ограничен 2, rAF стартует и
останавливается по IntersectionObserver, resize задебаунсен.

## Доступность

- Семантика: `main`, `section` с `aria-labelledby`, корректная иерархия заголовков.
- Skip-link к содержанию.
- Переключатель режимов AI — кнопки с `aria-pressed`.
- Полный отчёт — `aria-expanded` + `aria-controls`.
- Результаты навыков дублируются текстом для скринридера, а не только цветом точки.
- График распределения — `role="img"` с текстовым `title`.
- Canvas помечены `aria-hidden`, у карты есть текстовая легенда сегментов.
- Весь контент читается без скролл-анимаций: в `prefers-reduced-motion`
  секции показываются сразу, диалоги раскрыты целиком, полосы заполнены,
  preloader и Canvas отключены.

## Интерактив без внешних вызовов

Переговорное демо полностью клиентское: состояния диалога и реакции клиента лежат
в `demo-data`, пользовательский ввод никуда не отправляется. На странице явно
указано, что сценарий демонстрационный и не говорит о профессиональных качествах
посетителя.

## Видео

Hero-сцена сгенерирована через Higgsfield MCP и подключена:
`media/case-telecom/hero-signal.*` плюс отдельный вертикальный кроп для мобильных.
Источник подставляется скриптом по ширине экрана, загрузка стартует по
IntersectionObserver, при ошибке включается Canvas-фолбэк, в reduced-motion
остаётся только постер. Промпты, модели и команды пост-обработки —
в `docs/higgsfield-telecom-case-prompts.md`.
